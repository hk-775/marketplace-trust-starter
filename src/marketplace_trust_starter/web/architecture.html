Runtime topology

One process, clear modules, replaceable edges.

The starter is intentionally compact. Its service, engine, store, and web surfaces can be understood independently before any production integration is attempted.

Web and API boundary

  • Responsive landing, dashboard, and architecture pages
  • FastAPI validation and OpenAPI documentation
  • Profile, content, coordination, policy, review, audit, and reset routes
  • Security headers and same-origin browser calls

Application service

  • Loads a versioned policy snapshot
  • Generates assessment and case identifiers
  • Separates assessment from review state
  • Routes only high and critical scores to people

Deterministic engine

  • Named positive and counter-signals
  • Bounded point contributions and multipliers
  • Precision-sensitive compound conditions
  • No protected attributes, images, models, or network calls

Durable local state

  • SQLite assessments and evidence snapshots
  • Enforced human-review transitions
  • Editable and locked policy records
  • SHA-256 linked audit events and deterministic reset
